# Polymarket «Up or Down 15m» — бэктест (BTC / ETH / SOL / XRP)

Период: 18.08–25.09.2026, 14 672 окна. Источники:
- архив стаканов Polymarket https://archive.pendulumflow.com (эпоха v3, CC BY 4.0);
- Gamma API Polymarket (список окон, `priceToBeat` / `finalPrice` от Chainlink);
- секундные свечи Binance spot с data.binance.vision.

Правило исхода с 07.08.2026: Up выигрывает, если TWAP Chainlink за последние 60 с окна ≥ TWAP за 60 с до старта.
Комиссия тейкера: `0.07·p·(1−p)` за контракт. Мейкер платит 0.

python a_desc.py      # объёмы, сделки, спреды (-> data/trades_15m.parquet)
python a_proxy.py     # насколько Binance повторяет Chainlink

python a_strat.py     # стратегия 2, сетка параметров
python a_incidents.py # стратегия 2 без сбоев площадки, по неделям и половинам

python fav_factors.py # какие факторы отделяют хорошие сделки фаворита от плохих

Нужны: pandas, numpy, pyarrow, scipy, requests (duckdb — только для старых `pf.py` / `extract.py`).

## Что протестировано

**Стратегия 1 — купить фаворита или андердога по аску в момент T** (`a_calib.py`).
Моменты от 870 до 3 с до конца окна. Фаворит — сторона с mid ≥ 0.5. Корзины цены от 0.50–0.60 до 0.98–0.995.
Держим до исхода. Результат: у фаворитов от 0 до минуса нескольких центов на контракт, у андердогов хуже.
Прибыльных корзин после комиссии нет. «Плюсы» в последние секунды — это замёрзшие стаканы во время сбоев.

**Стратегия 2 — справедливая цена по Binance против котировки** (`a_strat.py`, `a_incidents.py`).
Каждую секунду считаем P(Up) по Binance с учётом TWAP-правила.
Покупаем сторону, если справедливая цена − цена покупки − комиссия > θ.
Параметры: θ = 3/6/10/15¢; задержка ордера 1/2/5 с, исполнение только если цена к моменту прихода не хуже.
Зоны: до последней минуты / последняя минута / всё окно. Одна сделка на сторону за окно.
Результат вне сбоев: при θ 3–6¢ около нуля или минус. При θ = 15¢ конец августа +9¢ (t≈5), сентябрь +2–3¢ (t≈1.2–1.6): преимущество затухло.
Внутри сбоев «плюс» доходит до +26¢ (t≈10), но это фантом: торговать было нельзя.

**Проверки:** Binance повторяет Chainlink с ошибкой ~0.3 б.п., исход совпадает в 99% окон.
Polymarket реагирует на Binance в ту же секунду, многосекундного отставания нет.

**Стратегия 3 — купить фаворита за 5 минут до конца, $3 на сделку, депозит $17** (`python a_fav5m.py 300 3 17`).
Вход рыночным ордером через 1 с после решения, фаворит — сторона с mid > 0.5, сбои исключены.
Итог (4 монеты, 12 893 сделки): вин-рейт 82.9% при безубыточном 84.4%, −1.4¢ на контракт, −$0.06 на сделку (−2.0%, t −3.8).
Депозит $17 обнуляется на каждой монете (BTC к 22.08, ETH к 05.09, SOL и XRP за 1–2 дня).
Вход за 10/3/2/1 мин тоже в минусе, за 30 с около нуля. Сделки → `data/fav300_trades.parquet`.

**Параметры стратегии фаворита, ставка $1** (выбор только на 18.08–04.09, проверка на 05.09–25.09):
- подбор «лучшей комбинации» — подгонка: топ-30 из 6 795 комбинаций +8.3% на истории → −1.5% на новых данных;
- устойчиво помогают: фильтр модели Binance (фаворит не переоценён), сторона в фаворитах все последние 5 мин,
  цена 0.80–0.98, спред ≤ 2¢; стоп-лоссы вредят, тейк-профит 0.99 чуть хуже, часы 12–20 UTC не подтвердились;
- **вход в первый момент, когда выполнены условия** (`a_trigger.py`) — лучшее улучшение: окно 6→3 мин, 12–20 UTC
  (выбрано на 1-й половине): +3.0% → на 2-й половине +2.0% на сделку, t 1.7, 29 сделок/день, вин-рейт 95%;
  без фильтра часов, окно 8→3 мин: +1.4% / +1.0% (t 1.4), 120 сделок/день. Фиксированный вход за 8 мин: 9 сделок/день;
- Chainlink вместо Binance (`a_chainlink.py`): разница «расстояния до цены старта» 0.35 б.п. (медиана), точность та же,
  стратегия не лучше — важно только в последние секунды;
- поток агрессивных сделок Binance (`a_flow.py`): информации нет (корреляция с движением до конца окна ≈ 0,
  знак коэффициента меняется между половинами);
- дневной лимит (`a_daystop.py`): ожидание не повышает (проигрыши почти не идут сериями), но режет просадку:
  окно 8→3 мин с лимитом −$2 в день — на 2-й половине +$21.9 вместо +$25.0, макс. просадка $11.4 вместо $16.8.
Всё это статистически ещё не доказано (t < 2 на проверочной половине) — нужен форвард-тест на новых данных.

**Не тестировалось:** мейкер + ребейты, 5-минутные рынки как отдельная стратегия, отставание меньше секунды, отставание альтов за BTC.

## Модель TWAP v2 (`twap2.py`, `a_twap2_strat.py`)

Вероятность Up = Student-t( d / √(k·σ̂²·h + sb²) ), где d — расстояние ожидаемого финального TWAP от цены старта,
h — «оставшееся время» по правилу усреднения, σ̂² — прогноз волатильности по 1 мин / 5 мин / 30 мин / 4 ч / суткам.
Подобрано на 1-й половине: веса волатильности 0.28·(1 мин) + 0.43·(5 мин) + 0.31·(30 мин) + 0.07·(4 ч) + 0.10·(сутки),
k = 0.78, шум Binance против Chainlink sb = 0.44 б.п., хвосты — нормальные (Student-t не понадобился).
Плюс «смесь»: логистика по цене рынка и модели с весами, зависящими от времени до конца.
Параметры: `data/twap2_params.json`, вероятности по секундам: `data/fair2_<tf>_<coin>.npy`;
в стратегиях: `features(..., model='new' | 'blend')` (по умолчанию `'old'`).

Итог на 2-й половине:
- точность выше старой модели лишь на 0.1–2% (Brier), но всё ещё хуже рынка: на 1–5 мин до конца на 1–3%,
  в последние 30 с — в разы (рынок видит сам Chainlink, у нас только Binance);
- смесь с рынком ≈ сам рынок (±1–3%); отдельные параметры для последних секунд и перекалибровка не помогли;
- как фильтр для стратегий v2 хуже старой модели (A15 +0.9% против +1.5%, B15 +0.4% против +0.9%, 5m тоже хуже):
  она увереннее в фаворитах 0.90–0.98 и пропускает лишние сделки. Старая модель консервативнее (волатильность
  за 30 мин и 4 ч) и лучше отсекает сделки перед всплесками волатильности. В замороженной стратегии остаётся старая.
Чтобы обогнать рынок в последние секунды, нужна настоящая цена Chainlink — её можно только записывать вживую.

## Бэктест с ликвидностью стакана (`a_liquidity.py`)

`python a_liquidity.py plan` → сделки вариантов A15/B15 × модель old/blend × фильтр 0/1¢;
`python a_liquidity.py pull 2026-09-05` → снимки стакана (asks) вокруг входов → `data/book15/` (~12 ГБ трафика за 2-ю половину);
`python a_liquidity.py sim` → исполнение по реальным уровням. Модель исполнения: последний снимок до прихода ордера
(вход + 1 с), уровни дешевле текущей лучшей цены уже съедены, новый лучший уровень (которого нет в снимке) = 5 контрактов
(минимальный лимитный ордер), ордер — «рыночный с потолком»: не дороже цены решения + 1¢, частичное исполнение разрешено.

2-я половина (05.09–25.09), на сделку:

| Вариант | Идеал | С ликвидностью $1 | $5 | $20 | $17 → (ставка $1) |
|---|---|---|---|---|---|
| A15 blend фильтр>1¢ | +2.01% | +1.88% (t 1.2) | +1.82% | +1.51% | $23.3 ($24.9 с лимитом −$2) |
| A15 old фильтр>1¢ | +1.94% | +1.58% (t 1.2) | +1.53% | +1.42% | $23.3 ($24.6) |
| B15 blend фильтр>0 | +0.51% | +0.47% (t 0.7) | +0.44% | +0.04% | $32.4 ($25.4) |
| B15 old фильтр>0 | +0.88% | +1.01% (t 1.3) | +0.98% | +0.52% | $39.5 ($36.5) |

- при $1 глубина не мешает (на лучшей цене обычно ~$85, проскальзывание ≈ 0); главное — в ~11% сигналов цена за
  секунду уходит выше решения+1¢, и сделки нет;
- при $20 полностью исполняется лишь 66–72% ордеров (в среднем $16–17.6 из $20), доходность падает на 0.3–0.9 п.п.:
  ёмкость стратегии — единицы долларов на сделку;
- смесь (blend) не лучше старой модели, кроме A15 с порогом 1¢ (в пределах шума); все t < 1.4.
Архив иногда отвечает 503 — в `rng.py` повторы с растущей паузой, загрузка в 3 потока.

## Форвард-тест (`python forward.py`)

Правила заморожены 25.09.2026 в `forward.py` (`FROZEN`, `VARIANTS`) — их нельзя менять, иначе это уже не форвард-тест.
Форвард-период начинается 25.09 00:00 UTC: эти окна бэктест не видел.
Каждый запуск:
- докачивает новые окна из Gamma, новые часы архива и секундные свечи Binance
  (дневные файлы, а для сегодняшнего дня — `data-api.binance.vision`, т.к. `api.binance.com` из США заблокирован);

- печатает сделки и итог, дописывает строку в `data/forward_log.csv`.
`python forward.py report` — только отчёт, без докачки.
